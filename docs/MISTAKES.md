# 這次做壞的每一件事，和它現在被什麼擋著

寫給下一次的自己。分兩半：**擋得住的**已經變成程式，**擋不住的**列在後面，
那份清單比前面那份重要。

## 一、已經變成門的（不做就過不去）

`core/script.py` 的 `measure()` 每一項都是一次真實的失敗留下來的。

| 門 | 當初怎麼壞的 |
|---|---|
| `unpicked` | 文案寫「真實：變電所」，檔案幾天後才挑 —— 寫的人沒看過有哪些圖 |
| `unchecked` | 憑搜尋詞挑圖，把一張**牆上的配電箱**標成「帳單特寫」 |
| `undrawn` | 29 個自製畫面只是 `show` 裡的一句描述，等人事後讀了去畫 |
| `uncredited` | 成品三段引用**全都沒有燒上 credit**，而台標還在所以不明顯 |
| `samey` | 結尾連續六張一樣的 `word` 卡，單張看都沒問題 |
| `unsigned` | 片子是「停下來」不是「結束」，沒有帶得走的話，也沒有頻道標記 |
| `shapeless` | 起承轉合檢查不了 —— 改成每句標 `role`，檢查那個宣告 |
| `over` | 長度**一直算得出來、網頁看得到、但擋不住任何東西**，90.78 秒照樣送去編碼 |
| `still_enough` | 五支影片下載回來只當截圖用，成品從頭到尾沒有一格會動 |
| `simplified` | 整份簡體，靠 `shapeless` 誤打誤撞攔到 —— 換個公版就會通過 |
| `card_wrong` | `bars` 的長度寫成「超過 1/3」，八道門過了，四分鐘後死在 ImageDraw |

## 二、已經變成流程的（不叮嚀，直接擺在眼前）

| 機制 | 取代了哪一句叮嚀 |
|---|---|
| `core/brief.py` | 「選之前要打開來看」→ 圖和它的 caption 已經排在你面前 |
| `brief.pick()` | 「檔名要抄對」→ 寫 `PICS["P18"]`，打錯當場爆 |
| `captions.passages()` | 「要剪在句子邊界」→ 給你的每個選項本來就在邊界上 |
| `build()` 的接觸表 | 「壓完要看一遍」→ 每次自動產，取樣由文案時間軸決定 |
| `topic.replace_images()` | 「小心不要先刪」→ 新的收齊才刪舊的 |
| 鏡頭檔名含程式指紋 | 「改了畫法記得重畫」→ 改程式就換檔名，舊檔自然找不到 |
| `script.for_topic()` | 「存檔時記得登記到題目上」→ 從文案反推，不存第二份 |
| `topic.facts_of()` | 「欄位名要打對」→ 讀的時候規定形狀，兩種寫法都收 |
| `topic.voice_count()` | 同上，留言的兩種存法都讀得懂 |

## 三、已經變成數字的（改一個地方，檢查和說明同時變）

`assets/rules.json`、`assets/theme.json`。以前每個門檻在程式和 prompt 各寫一次，
改一邊另一邊不會動 —— 網頁把三分之一實拍的文案報成「自製 100%」就是這樣來的。

# 擋不住的

**這份比上面那份重要。** 上面每一條都有程式頂著；下面每一條只能靠人或
視覺模型，而且我在這個 session 裡每一條都犯過。

## 1. 圖裡到底有什麼

`answers()` 給那張配電箱 0.5 分，給正確的帳單也是 0.5 分。
**沒有任何字串比對能分開它們。**

我試過兩版程式判斷「這是不是照片」——數顏色數量、量顏色蓋掉的面積——
兩版都把一張黑白照片排在國徽前面。**分不開的檢查比沒有檢查更糟，因為它會被相信。**

```
現在靠   我打開來看，填 seen
之後靠   視覺模型
擋不住的 我看了但看錯，或根本沒看就填 seen
```

這是第一階段「不要人為介入」唯一還缺的一步。

## 2. 那個「轉」夠不夠有力

程式檢查得到「轉」出現在前三分之一，檢查不到它有沒有翻轉任何東西。
換句話說、補充細節、把前面再講一次大聲一點——都會通過。

`core/critic.py` 的第二次呼叫是為了這個，但**還沒有金鑰，從來沒跑過**。

## 3. 觀點是不是素材裡沒有的

要翻遍所有素材確認沒有人這樣寫過。程式做不到。

## 4. 引用畫面上的字

新聞畫面自己帶著下標和數字。要 OCR 才擋得住，而 OCR 錯了更糟。
現在靠挑段落的時候自己讀。

## 5. 影片是不是真的在講這個題目

`unindexed()` 抓到了那支講老虎的 BBC，**但也誤報了一支完全切題的 AP**——
七個人講戰爭怎麼改變他們那一週，用的是加油和停車的字眼，不是「伊朗」和「戰爭」。

所以它被改名成它真正量的東西：**「這支影片能不能用字幕挑畫面」**。
「它是不是在講這個題目」還是沒人擋得住。

## 6. 事實有沒有被斷章取義

每一句都指得回某一篇，程式檢查得到。但「那一篇真的這樣說嗎」檢查不到。

## 7. 語氣對不對

死亡、疾病、災難不能開玩笑。哪些算、哪些不算，只有人知道。

## 8. 最後要不要發

硬檢查擋得住「有沒有」，擋不住「好不好」。**這一關是設計的一部分，不是還沒做完。**

## 沒有產出，不等於沒有錯

收集留言那一步跑了三支影片、存進零則，而工作報告「完成」。原因是
`read_comments` 回的欄位叫 `say`，我在收集那段寫成 `text` —— **憑記憶寫欄位名，
跟憑記憶寫檔名是同一件事**，只是檔名那三次有 `unpicked` 擋下來。

```
有門的     圖片路徑錯 → unpicked 當場說「找不到」
沒門的     欄位名錯   → 靜靜跳過每一則，然後說完成
```

**一個「做了 N 次、收到 0 筆」的步驟應該要出聲。** 現在沒有任何檢查在看
「做了但什麼都沒拿到」，而那正是最像成功的失敗 —— 跟 tunnel 斷掉被當成
「模型決定全部留著」是同一個形狀。

## 規則沒寫下來，比模型寫錯更嚴重

第一份 Qwen 文案整份是簡體，連角色都寫成「疑点」「悬念」。
`shapeless` 擋下來了，但**是靠運氣**：門只是不認得那四個字。
換一個公版，如果它的角色表剛好列了那兩個詞，整份簡體會直接通過。

而不能怪模型：**四份 prompt、六千字規則，沒有一句說要繁體中文。**

```
九道門     擋掉九種寫錯
零道門     擋掉「我沒說」
```

檢查最容易漏掉的，就是從來沒被違反過、以至於沒人想起要寫的那一條。
現在 `simplified` 逐字判（OpenCC 兩次轉換交叉比對），
`{language.name}` 從 `rules.json` 填進兩份 prompt —— 一個欄位，兩個用途。

順帶測出來：我自己寫的八份文案裡有兩處「群」被誤判，
因為 OpenCC 認為正字是「羣」。**先在真實資料上跑過再上線**，
不然新門第一件事就是擋掉正確的東西。

## 靜靜回報零，是這個專案最貴的失敗

一個晚上抓到六個，全部長一樣：**程式跑完了，數字是零，沒有人報錯。**

| 看到的 | 真正發生的事 |
|---|---|
| 每個題目「文案 0」 | `pile["scripts"]` 沒有任何寫入點，永遠是 `[]` |
| 「鄉民留言 0」 | 兩個寫入者格式不同，讀的人只認一種 |
| 存疑報導 0 篇 | SSH 通道斷了，判斷根本沒跑 |
| 兩張維基照片被丟掉 | 重複門檻 12 位元落在雜訊裡，肖像撞到遙控器 |
| 六支德語影片「沒字幕」 | 實際是沒影片：字幕 429 把整個下載帶走 |
| Reuters、Al Jazeera「沒報」 | 標題裡有 `|`，切錯欄位，網址變成 `SPIEGEL TV\|https://…` |

零看起來像答案。**「找到 0 筆」和「沒有去找」在畫面上長得一模一樣**，
而後者才是錯。

現在收集那一輪會把警告寫進題目檔案，不只寫進記憶體裡的工作日誌 ——
上一次那句 ⚠ 確實出現過，我重啟伺服器就把它清掉了，然後那個題目
看起來就跟「判斷過、很乾淨」完全一樣。

## 同一個模組裡兩個同名的 def

我在 `core/script.py` 加了 `too_long(measured)`。檔案下面**早就有一個**
`too_long(script)`，測的是完全不同的東西（台詞會不會被字幕區截掉）。
後定義的贏，所以：

```
build() 把 measured 字典傳給了要 script 的函式   長度檢查停止工作
錯的那個函式回空清單                          Python 當 false，JavaScript 當 true
網頁因此把每一支片都標成「超長 0s」              而壓片那邊完全不檢查了
```

**Python 不會警告。** 而 grep 抓不到（兩行長得不一樣），`ast` 一秒就抓到。
所以做了 `studio/checkpy.sh`，接進 pre-commit hook，掃 40 個檔案的最上層
def 和 class 有沒有重複。實測會攔。

順帶：那個舊的 `too_long` 幾個月沒有人叫過。改名 `clipped` 之後接成第 11 道門
—— 它測的東西（一句斷成三行還放不完，尾巴消失，只在燒上去的畫面裡看得到）
正是這個專案最在意的那類錯。目前九份文案零處，因為 13 字那條規則寫在寫作的
時候，而不是寫在事後檢查裡。

## 憑記憶寫欄位名，第三次

```
read_comments 回 say，我寫 text          三支影片、零則留言，顯示完成
收集寫扁平，網頁寫分組                    60 則留言存在檔案裡，頁面顯示 0
facts 是 {say, from}，我寫成純字串        頁面顯示 16 條，每一條都是 undefined
```

三次都不是程式壞掉，是**兩邊對同一個名字的認知不同**，而且三次都靜靜地
顯示零或 undefined。

擋不住「寫的時候打錯」，所以改成**讀的時候規定形狀**：
`facts_of()` 兩種型別都收，純字串就把句尾括號當出處拆出來 ——
那本來就是我寫的時候的意思。`voice_count()` 早幾個小時做過同一件事。

**一個只有一種寫法能過的欄位，遲早會有第二種寫法。**

## 兩份邏輯，一定會分岔

`samey` 數色調用 `card.tone or line.tone`；畫圖只讀 `card.tone`。
一份寫成 cool → light → warm 的文案，**過門時算三段，出編碼器是一片藍**，
而且沒有任何東西能報這件事 —— 兩邊都完全照著自己寫的做。

```
規則寫兩份     其中一份會過期，而且不會有人發現
規則寫一份     tone_of_line()，兩邊都叫它
```

同一個晚上還有一次：`assets/rules.json` 的門檻寫成
`def alike(one, other, within=12)` 的預設參數。數字只留一份，
包含預設參數也算一份。

## 範例會被當成答案

判斷相關性的 prompt 結尾是：

```
只輸出 JSON：{"keep": [1, 4, 7]}
```

30B 模型面對 36 個標題，原封不動回了 `{"keep": [1, 4, 7]}`。
**一個格式正確的範例，有時候就是它給的答案。**

而且問法本身是錯的。要它從 36 個挑「相關的」，是要它產生長清單；
改成問「哪幾個無關」，清單短，而且答錯的方向變成留下而不是丟掉 ——
留錯一篇的代價是清單多一行，丟錯一篇的代價是一條事實從此不存在。

## 八道門過了，然後在編碼器裡炸掉

`bars` 卡的長度欄位我寫了「超過 1/3」。八道門全部通過，
四分鐘後死在 `ImageDraw` 裡：`could not convert string to float`。

`undrawn` 問的是「有沒有卡」，沒有人問「這張卡畫得出來嗎」。
現在 `card_wrong` 問後面那一個。

**這個專案其他的畫面錯誤都是靜靜地錯，這一個是大聲地、很晚地錯。**
兩種都要擋，理由不同：前者沒人看得到，後者浪費四分鐘。

## 一個貫穿全部的形狀

這個 session 裡同一個錯出現了三次，每次長得不一樣：

```
批次編輯最後一步失敗    前面所有編輯一起丟
從舊字串重複 replace    後面的寫入蓋掉前面的，三節 prompt 消失且不報錯
先刪舊圖再抓新圖        抓到第三個詞失敗，47 張照片已經沒了
```

**都是「破壞已經發生，而產出還沒發生」。**
規則：破壞性的步驟永遠放最後。

還有一個形狀出現了三次：

```
憑記憶打影片檔名   RvGVUpVqE-Y  實際是 B06uPGK7Dpo
憑記憶打圖片路徑   兩次都是別的題目的圖，檔案存在，路徑看起來合理
```

門每次都攔下來了，但它一直發生。所以做了 `brief.pick()`——
**同一個錯犯三次，代表那個錯不該還能犯。**

# 接得上 API 嗎

寫在這裡，因為每一條修正的價值都取決於這個。

## 接得上（絕大多數）

```
measure() 的九道門    純程式，不管文案是誰寫的都會跑
rules.json / theme    資料
core/brief.py         它產生的就是要送出去的輸入
四份 prompt           本來就是要送給模型的
build() 的門、快取指紋、接觸表   純程式
replace_images / for_topic     純程式
批次存檔 + 順序檢查     在伺服器端，對任何寫的人都一樣
```

## 接不上，需要另外做

**`seen` 現在是我填的。** 換成 API 之後要有一次視覺呼叫來填，`brief` 還沒有
那一步。門在，填的人不在。

**`critic.py` 從來沒跑過。** 程式路徑接好了，沒有金鑰。

## 差點漏掉的一個

`brief.pick()` 讓我寫 `PICS["P18"]` 而不是打路徑 —— **但那只保護寫 Python 的我。**
模型回傳的是 JSON，路徑是它自己寫的，這個保護完全不存在。

實測：把家醫科文案裡的一張圖換成美伊題目的圖，**所有門都通過**，因為那個檔案
確實存在。

修法是把保護搬到門上：`missing_pictures()` 現在檢查那個檔案**是不是這個題目
收的**，不只是存不存在。影片段落也一樣。

**教訓**：一個只在「我用某種方式工作」時才成立的保護，換一種工作方式就消失了。
門要擋的是結果，不是過程。
