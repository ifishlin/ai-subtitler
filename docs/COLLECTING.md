# 素材怎麼收

## 一個新題目要找什麼

| 要什麼 | 幾個 | 去哪裡 |
|---|---|---|
| 影片 | 5 | `assets/sources/media.json` 裡 19 家的 YouTube 頻道，逐家搜 |
| 報導 | 5 | 同一份清單的官網。至少 2 中立 + 1 左 + 1 右 |
| 原始數據 | 1–3 | 財政部 Fiscal Data、CBO、FRED、Eurostat —— 能下載 CSV 的 |
| 圖表照片 | 幾張 | **新聞畫面上標的那個出處**。CNN 標了 PGPF，就去 PGPF 拿原圖 |
| 鄉民留言 | 每支影片 60 則 | 影片底下，yt-dlp `--write-comments` |
| 示意圖 | 5 張 | Pexels，可商用免標示 |
| 真實人事地 | 5 張 | **維基百科條目主圖**，查不到才搜 Commons。出處要上畫面 |
| 新聞畫格 | 5 張 | 從影片剪，**用字幕決定抽哪裡**，算引用額度 |
| 影片段落 | 2–3 段 | 同上，但剪在句子邊界。**至少要佔實拍的一半** |
| 事實清單 | 10–20 條 | 從以上全部抽出來，每一條標出處 |

三種照片各 5 張而不是「10 張照片」，因為它們不能互相頂替——詳見下面那節。

圖表那一列值得特別說：新聞台幾乎都會在畫面角落標出處，順著它回到原機構，
拿到的是**原始圖表和原始數字**，比搜圖精準，版權來源也清楚。而且原始資料
常常比新聞多——PGPF 那張長圖上有「每戶 $297,000」，CNN 只講了每人。

**驗收條件不是數量，是有沒有人不同意。** 左右各至少一則、中立至少兩則，
否則 `core/topic.py` 的 `ready()` 會擋住寫稿。

## 為什麼不能用搜尋

第一次做的時候，我搜尋了一次整個網路，得到零筆有用的結果。原因不是搜尋壞掉，
是問錯問題。

```
搜尋   問「網路上有什麼」  →  回來的東西彼此同意，因為結果第一頁彼此同意
清單   問「這 19 家各說了什麼」  →  每一家都被問到，答案自帶立場
```

第二種還有一個好處：**你知道是誰回答的**，所以立場標籤不用猜。

實測同一個題目，逐家問一輪就拿到右派兩支、中立四支：

```
Fox Business  13.4分  Bond market FLASHES warning      ← 右
Fox News       4.1分  Former Reagan budget director    ← 右
CNBC          12.2分  What Happens If The U.S. Can't Pay
Reuters       10.1分  What does $40 trillion mean       ← 中立
PBS NewsHour   5.6分  National debt nears $40 trillion  ← 中立
```

## 逐家問

影片：YouTube 的頻道內搜尋，yt-dlp 直接吃

```
https://www.youtube.com/@{channel}/search?query={關鍵字}
```

一家問一輪，每家只留第一支合用的。合用的條件：

```
120 秒 ≤ 長度 ≤ 2400 秒     太短沒東西剪，太長多半是整集重播
```

實測一輪（六家 × 五個題目）就把五支的額度全部填滿，而且每個題目都拿到
至少一則右派、一則中立。

報導：各家自己的搜尋頁，或站內搜尋的網址規則。

清單在 `assets/sources/media.json`，含每家的頻道代號、網站、立場、有沒有付費牆。

### 找到的當下就要記完整

第一次做的時候我只記了標題，結果一個四家都在報的大題目，頁面上顯示
「影片 0/5」。那不是頁面錯——**沒有網址的東西不能看、不能剪、不能查證，
那就不算素材**。

所以搜到的當下必須一起拿到：

```
url        沒有它就什麼都做不了
seconds    決定剪不剪得出東西
outlet     對得上清單，立場才有依據
lean       從清單查，不是用猜的
```

搜尋指令一次就給得出這些，分兩次做只會弄丟：

```
yt-dlp "{頻道搜尋網址}" --flat-playlist --playlist-end 8 \
       --print "%(duration)s|%(title)s|%(webpage_url)s"
```

### 線索和素材要分開

在頻道清單裡「看到」不等於「拿到」。看到的叫線索，只是知道它存在；
抓回來、量過長度、確認有字幕的才叫素材。

**計數只算素材。** 讓線索灌進去會得到一個看起來很豐富、實際上什麼都做
不了的題目——這比顯示 0 更糟。

## 照片：三種來源，各補不同的洞

「十張照片」是錯的單位。一個圖庫沒有馬杜洛的照片，也沒有那個被沖走的村莊
——那些不是概念。Commons 有，但它沒有「排隊」「帳單」這種讀得出意思的畫面。
而兩者都沒有事情發生當下的樣子。

所以是**三種各 5 張**，而且不能互相頂替：

| 類別 | 從哪來 | 用在哪 | 授權 |
|---|---|---|---|
| **示意圖** | Pexels | 抽象的東西——帳單、電表、排隊、機房 | 可商用免標示 |
| **真實人事地** | Wikimedia Commons | 有名字的人、街、建築 | 多為 CC BY／BY-SA，**出處要上畫面** |
| **新聞畫格** | 這個題目自己的影片 | 事情發生當下 | 引用，**算在 25% 額度裡** |

頁面上分三區顯示，因為「三十張示意圖、零張真實照片」不算齊，數字再大也一樣。

### 示意圖：多樣性比數量重要

第一次抓的時候我用四個搜尋詞、每個拿六張，得到「六張油桶、六張煉油廠」。
數量二十四張，能用的角度只有四種。

**六張同一個搜尋結果，是六張同一個東西。** 多樣性來自多問幾個問題，
不是同一個答案多拿幾張。

```
每個搜尋詞最多  3 張
搜尋詞          8 到 10 個
```

搜尋詞**照文案會用到的畫面去想**，不是照題目去想：

```
題目：AI 資料中心推高電費

不好   AI、data center、electricity        三個都是同一件事的三種說法
好     electricity bill    帳單特寫，講到錢的時候用
       electric meter      電表，講到用量
       data center servers 機房，講到耗電的來源
       power grid          電網，講到區域性
       power lines suburb  社區電線桿，講到「你家跟機房共用一條線」
       family kitchen      一般人家裡，講到誰在付
```

每一個詞對應**文案裡的一句話**，抓回來才用得上。

### 搜尋詞說的是你想要什麼，不是你拿到什麼

`electricity bill` 搜回來一張牆上的白色配電箱。**Pexels 是拆成單字比對，
不是整句片語**：`electricity` 對到說明裡的 `Electrical`、`bill` 對到
`billing`，兩個字都在，所以它回傳了。

它的說明白紙黑字寫著 `fuse box`。**資料一直都在，是我沒看。**

所以每張圖要存兩樣東西，而且要在網頁上並排顯示：

```
term      你下的搜尋詞      electricity bill
caption   圖庫自己的說明    Electrical meter and fuse box on a white wall
```

兩行不一致就是抓錯了，**收集當下就該丟掉**，不要留到寫文案時才發現——
`ready()` 只數數量，答非所問的圖在帳面上看不出來。

### Wikimedia Commons：先查維基百科，不要搜

Commons 的錯法跟圖庫相反：**問對名字就給對的，問概念就亂給**
（`server rack` 搜到腳踏車停車架）。

所以有維基百科條目的東西，**直接拿條目的主圖，根本不要搜**：

```
https://en.wikipedia.org/api/rest_v1/page/summary/{條目}  →  主圖網址
```

一個呼叫，不用排序、不用判斷。百科已經替你決定哪張照片是這個人了，順便
拿到作者和授權。查不到條目就跳過——那是誠實的答案，比硬給一張最相近的好。

程式在 `core/stock.py` 的 `wiki_lead()`。搜尋只留給沒有條目的東西。

### Wikimedia Commons：兩個踩過的坑

**一、它會回 429。** 兩個原因，都要處理：

```
User-Agent 要說明你是誰、怎麼聯絡     video-pipeline/1.0 (...; 專案網址)
不能連發                            每次請求之間停 1.2 秒
```

用預設的 agent 或連打十次，一律被拒。

**二、單字搜尋會亂配。** `server rack` 搜到「腳踏車停車架」。改成引號片語，
或用分類搜尋：

```
filetype:bitmap "完整片語"
```

**三、授權要跟著圖走。** Commons 上幾乎沒有真正的公有領域，多數是 CC BY 或
CC BY-SA——**作者和授權條款要出現在畫面上**。所以抓的時候就把 credit 存進
記錄，不要留到後面再查，因為後面不會有人查。

### 新聞畫格

從這個題目自己的影片剪。作法是先下載影片（含字幕），再按時間點抽格：

```
每支影片抽 3 到 4 張，平均分布在整支片長上
```

分散是刻意的——新聞畫面每幾秒就換一次，有用的那張很少在開頭。

**畫格是最便宜的引用**：沒有接縫、沒有聲音、想停多久都可以。所以 25% 的
引用額度，用畫格比用影片片段划算得多。

### 去重

每張縮成 8×8 灰階、記錄哪些像素高於平均，兩張差不到 12 個位元就丟掉一張。

這道擋的是**真正的重複**——同一批攝影、連拍。「同一個主題的不同照片」
是另一回事，靠上面的配額擋。實測 30 張裡相似度過高的有 0 對。

### 一個詞失敗，只賠一個詞

第一版的寫法是：任何一次搜尋出錯就整批 502。連續打五個詞，被擋一次就
全部白做。

現在失敗的詞記下來跳過，其餘照跑。

## 湊不滿的時候，照順序放寬

一輪不夠就往下一輪，**每一輪都會擴大結果**：

| | 放寬什麼 | 例 |
|---|---|---|
| 1 | 照題目逐家問 | `national debt 40 trillion` |
| 2 | 換關鍵字 | 英文、數字、人名、同義詞 |
| 3 | 放寬日期 | 這週沒有就找這個月 |
| 4 | 放寬題目 | 「40兆」→「國債」。Fox 談國債一樣給得出右派論點 |
| 5 | 跟著引用走 | CNN 引 PGPF、Al Jazeera 引財政部 |
| 6 | 記下失敗 | 「右派試過這些關鍵字，沒有」 |

前五輪是機器做得到的。第六輪不是失敗，是誠實——有些題目就是一面倒，
硬湊反方是假的，而且看得出來。

## 該留下什麼

每一筆都要能回答「這是誰說的」：

```
title      標題
outlet     哪一家（對得上清單，立場才有依據）
lean       立場，從清單查，不是用猜的
url        原始網址
seconds    影片長度
captions   有沒有字幕（決定讀不讀得到內容）
facts      抽出來的事實，每一條都要能指回原文
```

## 鄉民反應

影片和報導底下的留言是**素材的一部分**，不是附屬品。理由：

- 它告訴你**一般人卡在哪裡**——那正是需要解釋的地方
- 它給你**真實的用語**，比新聞稿的說法更接近觀眾
- 它常常包含**新聞沒提的角度**

留言用 yt-dlp 抓（`--write-comments`），報導的留言區各家不同，多半要另外處理。

要留下的：文字、按讚數、時間。**不要留使用者名稱**——那是別人的個資，
我們要的是說了什麼，不是誰說的。

## 一個原則

素材夠不夠，看的不是數量，是**有沒有人不同意**。

五篇彼此同意的報導寫出來是宣傳，八分鐘的影片撐不住，而且 YouTube 的
人工審查會看出來。所以平衡檢查是擋住寫稿的條件，不是提醒。
