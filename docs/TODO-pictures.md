它現在打開了，下面〈看圖那一步〉整節就是它。程式在 `core/captions.py`、

## 看圖那一步 —— 還沒有人做

`seen` 這個欄位現在是**寫文案的模型自己填的**。它拿到的只有一行說明
（`[P13] 太空站拍的安大略湖`），從頭到尾沒看過那張圖，而 `visual.md` 要它
標 `seen: true`，它就標了。

所以 `unchecked` 那道門現在**擋不到任何東西** —— 它檢查那個字在不在，
而那個字一定在。真正在擋的只剩「收集時被人標成可疑」的那幾張，
跟模型寫的 `seen` 無關。

**這是一個宣告，而它宣告的是一件它做不到的事。**

### 該長什麼樣

```
第一輪  給清單（只有文字說明）→ 模型挑 P13、C8、V7，**不寫 seen**
第二輪  一張一張：這張圖 ＋ 那一句台詞 → 「有哪裡對不上」
        看得到圖的那一邊（人、或視覺模型）才填 seen
壓片    門這時候檢查「有沒有人填」，那才有意義
```

- [ ] `visual.md` 拿掉「要標 seen」那一條
- [ ] `writer.fasten()` 不要幫情境影片補 `seen`
- [ ] 新增 `core/looked.py`：一張圖 ＋ 一句台詞，問一次
- [ ] `unchecked` 的說明改掉 —— 它現在寫的是「有人聲稱看過」，
      而實情是「模型聲稱看過」

### 三個設計決定，理由寫在這裡免得下次重想

**一張一張問，不要併進寫文案那一份 request。**
三十五張全塞進去，等於為了用到的十三張付三十五張的錢；而且模型還沒挑，
你不知道要問什麼。更要緊的是問題不一樣：寫文案問「怎麼講這件事」，
看圖問「這一張是不是這一句講的東西」—— 後者混在同一份長 prompt 裡，
它會順著自己剛寫好的文案說「是」。**你在問它一個它剛剛才做過的決定。**
失敗的粒度也不同：分開問錯一張退一張，併著問錯一張退整份。

（形狀跟 `core/facts.py` 的 `ask_one()` 一樣：一段字幕問一次。）

**第二輪不要給它自己的理由。** 只給圖和那一句話，不要附上「你剛剛說要用
這張因為…」—— 那會讓它替自己辯護。

**問法要挑錯的方向。** 問「這張對嗎」預設答對；問「這張有哪裡跟這句話
對不上」清單空的才叫過關。這條 `assets/prompts/` 裡已經記過：
**選那個答錯了損失比較小的問法。**

### 對不上的時候怎麼辦

```
A  退回重寫整份    最貴，而且把對的那三十三句一起丟掉
B  只退那一句      那一句 ＋ 剩下的候選再問一次「換哪一張」
C  降級成卡片      改成自製卡片，不用圖
```

**B 為主、C 保底**：B 試兩次還挑不到就走 C。有些句子根本沒有對的圖存在，
一直重挑會卡在無窮迴圈，而卡片永遠畫得出來。

陷阱：**換掉圖之後實拍比例會掉。** 換兩三張還好，換十張就可能跌破
`borrowed.least` 那條線，然後被 `cardbound` 擋下來。換完要重新量一次，
不能假設還過得去。C 也一樣 —— 卡片變多、實拍變少，同一個問題。

### 誰來看

cuba001 上八個模型**沒有一個看得到圖**（gpt-oss、qwen3 系列全是純文字）。
所以這一步卡在「誰來看」，不是卡在程式：

```
A  cuba001 拉一個視覺模型   qwen2.5-vl:7b 之類，CPU 跑得動，慢但免費
B  Claude API               key 的位置已經留好，還沒設定
C  人來看                   最準，但這正是「要記得去做的動作」那一類
```

程式那一半不管誰看都一樣。


挑錯圖的原因：**照搜尋詞挑，沒打開來看。**

搜 `electricity bill`，Pexels 拆成單字比對，`electricity` 對到 caption 裡的
`Electrical`、`bill` 對到 `billing`，於是回來一張牆上的白色配電箱。它的
caption 白紙黑字寫著 `fuse box`，而我只看了自己下的搜尋詞。

三種來源錯的方式不一樣，所以分開列。

## 新聞畫格

現在是平均分布盲抽 3 到 4 張，抽到什麼純看運氣：訪談、片頭、主播大頭。
我把一張「兩個人坐著對談」標成「渦輪機特寫」，就是這樣來的。

```
1  門檻      沒字幕的影片不當畫格來源
2  選時間    從字幕挑講到主題名詞的句子，不是平均分布
3  取樣點    取那句字幕的中段，避開換場
4  記錄      每張存下 時間、那句字幕原文、影片出處
5  確認      看圖核對畫面是不是那句在講的東西
6  修正      不符就前後挪 ±2 秒重抽，兩次不中就換一句
7  去重      同一句抽到的連續格幾乎一樣，照舊用感知雜湊擋
8  台標      不裁掉頻道浮水印，那是 credit
```

字幕已經跟影片一起下載了（`bring_in` 有抓），只是沒拿來用。

**畫格分兩批**：收集時用題目關鍵字先抽一批墊底，寫到某一句再針對那句補。
後者準得多，因為關鍵字是「那句話要什麼」而不是「這題目在講什麼」。

沒字幕的影片就不當畫格來源。跑 Whisper 也行（cuba001 約 90 秒一支），
但 5 支影片通常至少 3 支有字幕，畫格夠用，不值得為少數情況寫程式。

## 真實人事地（Commons）

Commons 的錯法跟 Pexels 相反：**問對名字就給對的，問概念就亂給**
（`server rack` 搜到腳踏車停車架）。

- [x] **改走維基百科條目的主圖**——最簡單，先做這個

      ```
      https://zh.wikipedia.org/api/rest_v1/page/summary/{條目}  →  主圖網址
      ```

      一個呼叫，不用搜尋、不用判斷，順便拿到作者和授權。查不到條目就跳過。

- [x] 只問專有名詞：人名、地名、建築名。概念交給 Pexels
- [x] 用 Commons 的 `depicts` 結構化欄位，比檔名可靠
- [x] 仍要看圖——主角對，但可能是雕像、背影、人群中的一張臉
- [x] `credit` 抓的時候就存（已做，別退回去）

## 為什麼不能只靠程式檢查

`missing_pictures()` 檢查「有沒有指定圖、檔案在不在」，這兩件事都通過了，
圖還是錯的。**程式檢查得了存在，檢查不了像不像。**

## 網頁上要多顯示什麼

錯的圖之所以活到成品，是因為**頁面上看不出它錯**。頁面顯示的是我打的
`show` 標籤，而標籤是自由文字，沒有任何東西跟圖本身對照過。

所以上面每一項改動，都要有對應的東西出現在 `studio/static/scripts.html`：

### 素材區的每一張圖

- [x] **caption**（Pexels 的 alt、Commons 的檔案說明）顯示在縮圖底下
- [x] **`term`** 也顯示，跟 caption 並排——**錯就錯在這兩者不一致**，
      並排才看得出來（`electricity bill` vs `fuse box`）
- [x] **來源和授權**：Pexels 免標示，Commons 要作者和條款，畫格要頻道名
- [x] **看過了沒**：未確認／我看過／LLM 看過，三種狀態
- [x] 新聞畫格多顯示 **時間點** 和 **那句字幕原文**

### 文案每一行旁邊

現在縮圖旁邊只有 `show`。要加：

- [x] 該圖的 **caption**，就在 `show` 底下——這樣「示意：帳單特寫」和
      `fuse box` 會並排出現，說謊的標籤自己會現形
- [x] **不符的警告**：LLM 判定圖跟 `show` 不符時標紅，跟 `unpicked`
      一樣進 `measure()` 的回報裡

### 檢查列

`measure()` 現在回 `unpicked`（沒指定圖）。要加一個 `unchecked`
（指定了但沒人看過），頁面跟 `unpicked` 一樣列出來擋著。

**指定了圖不等於圖是對的。** 現在頁面上這兩件事看起來一樣。

## 一定要有影片

整支短片目前是 PIL 畫的靜態圖送進 ffmpeg，**沒有任何一個輸入是影片**。
5 支影片下載回來只當截圖來源，動態完全沒用到。

`core/shorts.py` 的 `render()` 本來就會剪影片段落——手做那支 CNN 短片就是
這樣剪的。是 AI 這條路走 `build.py`，兩條沒接起來。**不是做不到，是我沒接。**

COLLECTING.md 裡「畫格是最便宜的引用」那句話沒錯，但它變成了不用影片的
藉口。**無旁白的片子，動態正是最能留住人的東西。**

### 新的比例規定

```
外部素材      佔總長 25%（上限 35%）      不變
其中影片段落  至少佔外部素材的一半         新增
```

**這兩個數字後來都改了。** 上限那一條的另一面沒有人守，成品變成一張卡接
一張卡，所以現在是**下限 50%、上限 65%**，外加 `cardbound` 那道門。
現在的值一律看 `assets/rules.json` 的 `borrowed` —— 這裡寫的是當時的決定，
不是現在的規格。

90 秒的片子換算下來（照當時的 25%）：

```
外部素材   約 22 秒
影片段落   至少 11 秒   ——  大約 2 到 3 段，每段 4 到 6 秒
靜態畫格   其餘         ——  帳單、電表、人臉這類停得住的
```

- [x] `measure()` 加 `clip_share`：影片秒數 ÷ 外部素材秒數，
      低於 50% 要跟 `unpicked` 一樣擋著
- [x] 文案的行要能指定**影片段落**而不只是 `pic`：
      來源影片、起訖秒數。`show` 開頭多一種寫法
- [x] `build.py` 的圖片路徑要能接 `shorts.render()` 的段落輸出
- [x] 段落用字幕挑（跟畫格同一套邏輯），並且**剪在整句的邊界上**，
      `tidy_edges()` 已經在做這件事
- [x] ~~靜音。影片的聲音一律不要——Content ID 比對的是音軌~~
      **後來推翻**：現在保留原聲。理由和代價寫在 `assets/rules.json`
      的 `sound.why`，以及 `core/shorts.py` 的 `clip_cut()`。
- [x] 台標不能裁掉，那是 credit
- [x] 網頁上影片段落要能播，不能只顯示一張縮圖

### 該用影片還是靜圖

```
用影片    事情在發生        現場、群眾、機具在轉、有人在說話
用靜圖    要看清楚一個東西    帳單、電表、圖表、一張臉
用卡片    在講道理          判斷、提問、結論
用情境影片 需要畫面在動，但這件事沒有現場畫面    ← 後來加的第四種
```

第四種是共用池子裡的情境影片：會動，但**不算實拍**。看 `/shots` 那一頁。
