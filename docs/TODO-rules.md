# 要改的清單

**全部做完了**，除了 10（審稿人要等 API 金鑰，程式路徑已經接好，
`core/critic.py`，現在會誠實回報「沒問到」而不是假裝通過）。

程式：`core/rules.py`（數字）、`core/brief.py`（把素材擺到眼前）、
`core/critic.py`（第二次呼叫）。資料：`assets/rules.json`、`assets/theme.json`、
`assets/prompts/{collect,script,look,visual,review}.md`。


出發點是這個 session 學到的一件事：**寫在文件裡的規則會被違反，被程式檢查的
不會。**

這個 session 裡沒有破過的規則，全部是 `measure()` 會算的（13 字、90 秒、
每句要有來源、實拍不超過 35%）。破掉的，全部只是寫在文件裡的：

```
選圖之前要打開來看      → 把配電箱標成「帳單特寫」
出處要上畫面            → 第一版影片三段引用全都沒有 credit
一半的實拍要會動        → 前幾支片一格都沒動
```

而且那三條都是我自己寫進 `script.md` 和 `COLLECTING.md` 的，讀過至少兩次。

## 兩種規則，成功率差很多

```
A 規範「寫出來的東西」   13 字、結論落在誰身上、數字要念出來
                        —— 一邊寫一邊就在遵守，機率高

B 規範「要做的動作」     打開圖來看、先排接觸表、從字幕挑時間點
                        —— 是離開寫字去做另一件事，機率低
```

**這次違反的全部是 B，一條 A 都沒破。** 所以送 prompt 對 A 有效，對 B 幾乎沒用。

B 只有兩條路：變成流程的一步（東西直接擺在眼前），或變成過不去的門。

## 順序

### A. 補硬檢查

- [x] **2. credit**　引用畫面沒有 credit 就拒絕輸出
      現在唯一還開著的洞。`clip_cut` 只在**裁切**時才拒絕沒有 credit 的畫面，
      而我們不裁切，所以第一版影片安靜地少了三行字。台標還在，所以不明顯，
      但我們畫在自己畫面上、任何裁切都拿不掉的那個標記是空的。

- [x] **1. role**　每句標 起／承／轉／合
      「要有起承轉合」檢查不了，但**「有沒有」幾乎都檢查得了**——做法是逼它
      把判斷講出來，然後檢查它講的那句話：

      ```
      四種角色都出現了嗎      順序對嗎（轉不能在承前面）
      轉出現在前三分之一嗎    每一段至少幾句
      ```

      範圍一下子從「整篇結構對不對」縮成「這一個轉夠不夠有力」。

- [x] **3. term ≠ caption**　收集當下就丟掉答非所問的圖
      `ready()` 只數數量，帳面上看不出來裡面有幾張是錯的。

### B. 把動作變成流程

**把「請你記得做 X」改成「X 已經在你面前了」**，這是唯一真正有效的一招。

- [x] **4. 寫文案的輸入自帶候選圖的接觸表**
      不是「請你去看」，是「圖在這」。

- [x] **5. 影片段落只能從 `passages()` 的清單挑**
      不是「請你剪在句子邊界」，而是給出來的每個選項本來就在邊界上。
      （抽格已經這樣做了，段落還沒。）

### C. 數字和說法各留一份

- [x] **7. `assets/rules.json`**　所有數字和門檻搬出程式

      ```
      13 字、3 行、4.6 字/秒、1.9 秒下限
      25% / 35% / 50%
      影片 5、報導 5、照片三種各 5
      平衡條件（左≥1、右≥1、中立≥2）
      每個搜尋詞最多 3 張
      ```

      程式從這裡讀，**送 prompt 的時候也從這裡填**（md 裡寫 `{PER_ROW}`）。
      改一個地方，檢查和說明同時變。現在這些數字在 `core/script.py` 和
      `script.md` 各寫一次，改一邊另一邊不會動——網頁報「自製 100%」就是
      同一種病。

- [x] **9. `assets/theme.json`**　配色、字級、版面座標搬出程式
      三組 tone 的顏色、卡片字級、`CAPTION_BOTTOM`、`PICTURE_TOP`、推鏡幅度。

- [x] **6. prompt 拆成四份**

      ```
      collect.md   搜尋詞怎麼想、什麼算合用
      script.md    文案（把卡片那段拆出去）
      look.md      看圖：這張圖是不是那句要的
      visual.md    卡片字彙、tone、fit 怎麼選
      ```

      現在只有 `script.md`，而且**沒有任何程式讀它**——13 KB 從來沒被送給
      任何模型過，只有我讀過。

- [x] **8. 留下來的改寫成「反例 + 為什麼」**
      刪掉能被 A 擋住的條文。**反例比正例有用，理由比規則有用**——規則只
      涵蓋你想過的狀況。

### D. 審稿人

- [x] **10. 第二次呼叫當審稿人**
      只問一個問題：「這個轉是真的翻轉，還是換句話說？」
      **第二次呼叫比自我檢查可靠得多**，因為它手上沒有寫作任務要顧。
      要等 API 接上。

### 另外欠著的

- [x] **11. `fit`**　靜圖怎麼放進直畫面：`fill`（裁成滿版）／`ground`（配
      當段 tone 的底色）／`blur`（模糊放大，現在的做法）

      模糊放大永遠不會錯，代價是平庸而且每張都長一樣。主角是直的（電塔、人、
      單一物件）裁成滿版更有力；橫的場景配底色，靜圖和卡片才像同一部片。

## 改完以後你能調什麼

```
數字   改 assets/rules.json      13 字改 12、引用 25% 改 20%、影片收 8 支
外觀   改 assets/theme.json      換配色、字級、字幕位置
內容   改 scripts/*.json         台詞、秒數、用哪張圖、卡片形狀和顏色
說法   改 assets/prompts/*.md    什麼算觀點、哪句該用影片
```

**數字改 JSON、說法改 md、程式只放做法。**


## 做完之後的狀態

```
門（不做就過不去）   沒指定圖　沒看過　沒畫卡　沒出處　結構　會動的比例
                    長度　字數　三段分布　每句要有來源
說明（只能靠說）     什麼算觀點　語氣　結論落在誰身上　哪句該用影片
                    —— 全部搬進四份 md，數字用名字寫，送出前才填
```

`script.md` 從 13.1 KB 縮到 5.5 KB，不是因為刪掉規則，是因為**能檢查的那些
已經變成門了**，prompt 裡只要提一句。

一個沒解決的：`answers()` 分不出那張配電箱和正確的帳單，兩張都是 0.5。
沒有任何字串比對能分開它們——**這就是 `seen` 存在的理由**，也是接上視覺
模型之前，第一階段還缺的那一步。
