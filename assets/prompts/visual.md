# 每一句配什麼畫面

一句台詞一個鏡頭。你要決定**哪一種鏡頭，以及那個鏡頭長什麼樣**。

## 四種鏡頭

```
用影片    事情在發生        現場、群眾、機具在轉、有人在說話
用靜圖    要看清楚一個東西    帳單、電表、圖表、一張臉
用卡片    在講道理          判斷、提問、結論
用情境影片 需要畫面在動，但這件事沒有現場畫面
```

早期的片子**一律用靜圖，等於把第一類也當成第二類處理**，成品從頭到尾
沒有一個畫面在動。無旁白的片子，動態是唯一還在動的東西——
一張人群的照片沒辦法說「事情正在發生」。

**情境影片不是證據。** 它是一支「夕陽下的電塔」，跟這個題目沒有關係，
所以：

```
可以   讓一句過場的話不要停在靜止的畫面上
可以   當一段的開頭或收尾的空景
不行   拿來代表「這件事的現場」
不行   配在一句有出處的事實上 —— 那會讓觀眾以為那是真的畫面
```

它**不算進外部素材的比例**（下面那一節的下限，只有真實照片和新聞片段
算數）。也就是說，多用情境影片不會讓你少用實拍，只會少用卡片。

## 比例

```
外部素材      佔總長 {borrowed.aim:pct}（下限 {borrowed.least:pct}、上限 {borrowed.most:pct}）
其中影片段落   至少佔外部素材的 {borrowed.clip_least:pct}
出現節奏      每三分之一的時間至少一次
```

上面那兩條相乘，就是影片段落的下限：**至少佔總長 {borrowed.clip_share:pct}，
{length.limit_seconds} 秒的片子就是 {borrowed.clip_seconds} 秒**。其餘的外部素材用照片補滿。

**段數自己算**：拿 {borrowed.clip_seconds} 秒去除素材清單上那些段落的長度
（每一段旁邊都標了秒數），通常會是四到六段。起訖不用你寫，程式從清單填。

照片補得越多不會讓你少放影片 —— 實拍一多，「一半要會動」要的秒數跟著變多。

兩條線都會擋。上限那條罰的是整個頻道 ——
**別人的畫面佔比一高，YouTube 會判定內容不是我們的**。
下限那條擋的是另一件事：**卡片超過一半，成品就是有聲音的簡報**。

下限一定湊得到，因為**同一張照片可以用在好幾句上**。
湊不到只有一個意思：沒有把收回來的東西看過一遍。

## 影片段落

```json
{"show": "影片：CNBC 渦輪機工廠的產線", "clip": "C3", "seen": true}
```

**只寫編號。** 檔案、起訖、長度都由程式從候選清單填 —— 那些起訖已經落在
字幕的句子邊界上，自己填數字會從半句開始。剪出來會**保留原聲**。

## 情境影片

```json
{"show": "情境：夕陽下的高壓電塔", "stock": "V7"}
```

`show` 一定要以 **`情境：`** 開頭 —— 那個前綴就是程式判斷「這不是實拍」的
依據，寫成「影片：」會被當成新聞片段，然後在門那裡炸掉。

沒有起訖，也不用標 `seen`（池子裡每一支都已經有人看過才留下來）。

（這裡本來的範例寫的是 `{"file": "…xxx.mp4", "start": 46.0, "end": 51.6}`，
跟 `script.md` 的「寫檔名一定會錯」正面衝突。那時候這個檔案根本沒有被送進
prompt，所以沒有人發現。）

## 用到別人的畫面，那一句要標 `seen`

```json
{"show": "太空站拍的安大略湖", "pic": "P13", "seen": true}
{"show": "影片：川普在橢圓形辦公室簽署", "clip": "C8", "seen": true}
```

**照片和影片段落都要，漏了那一句會被門擋下來、整份退回。**

程式檢查得到檔案在不在，檢查不到那張圖是不是那句話講的東西 —— 一張標著
「帳單特寫」的圖實際上是牆上的配電箱，那兩件事在程式眼裡一模一樣。所以
`seen` 是一個**宣告**：有人確認過這張圖配這句話。

你手上只有 caption 那一行字，看不到圖。所以只有在 caption 講清楚了那張圖是
什麼、而且跟你的句子對得上的時候才標。**看不出來就換一張**——素材表裡有
三十幾張。

## 靜圖怎麼放進直畫面

橫的照片放進 9:16，總有空間要填。填法是**對這張照片的判斷**，不是預設值：

```
fill     裁成滿版。最有力，但丟掉三分之二的寬度
         —— 主角是直的（電塔、人、單一物件）用這個
ground   配當段 tone 的底色。靜圖和卡片才像同一部片
         —— 橫的場景（廠房、街景）用這個
blur     模糊放大的自己當底。永遠不會錯，也因此每張都長一樣
         —— 挑不出來才用
```

## 卡片要指定怎麼畫

`show` 寫「自製：一條線分岔成兩條」是不夠的——那句話要有人事後讀了去畫，
**跟把配電箱配到帳單那句話上是同一種拆法**：寫的人沒看過，畫的人不知道為什麼。

```json
{"show": "自製：一條線分岔成兩條",
 "card": {"kind": "split", "title": "他們算的不是同一件事",
          "branches": ["發電\n夠不夠", "電線\n夠不夠"], "tone": "light"}}
```

字彙：

```
word    一句話佔滿畫面 —— 最常用，也是預設
number  一個數字，會從 0 跑上去      title / value / under / colour / ghost
ring    一個詞，手畫一個圈把它圈起來   title / value / under
swap    劃掉舊的，換上新的           title / was / now
bars    兩三個量比大小              title / rows[[名稱, 數值, 顏色, 標籤]]
split   一條線分岔成兩條             title / branches[兩個]
chain   同一條線上的幾個點           title / points[] / under
queue   一排排隊的人                title / count / under
stack   一份清單                    title / items[]
clock   一段年數，畫成圈             title / value / part(0–1) / under
```

共通欄位：`note` 是出處（畫在畫面頂端）、`ghost` 是背後放大的一兩個字。

**顏色欄位（`colour`、`bars` 每一列的第三格）只有兩種寫法**：留空，或者
`#ff7a4d` 這種色碼。留空是預設，也通常是對的——空的會用那一段 `tone`
自己的顏色，整支片才像同一部片。

寫 `ok`、`warn`、`red` 這種代號會**過了所有的門，然後在畫圖的時候炸掉**：

```
ValueError: unknown color specifier: 'ok'
```

（現在有門擋了，但擋下來的代價是整份退回重寫。）

## 最後一句一定是結尾頁

```json
{"say": "整件事是這樣的。", "role": "合", "show": "自製：結尾頁",
 "seconds": {ending.seconds},
 "card": {"kind": "outro", "tone": "cool",
          "points": ["電價漲了 7.1%，是通膨兩倍", "不是機房多用了電",
                     "是接電網要排七年", "那條線的錢照人頭分攤"],
          "title": "你付的不是他們用的電\n是他們插隊用的那條線",
          "under": "題目一句話"}}
```

`points` 是**摘要**，{ending.points} 條。看完九十秒的人拿到的是「讓論證成立的
順序」，而那個順序**不等於他帶得走的順序**——所以要重講一次，把整件事收成幾個步驟。

`title` 是**一句帶得走的話**，跟收尾論證的那一句通常不一樣：那是講給正在聽的人聽的，
這是講給等一下要轉述給朋友的人聽的。

版面是用時間堆出來的，不是用空間：摘要一條一條進來、結論在最後一條之後才落下、
頻道標記再更後面。**一次全部印出來就是一面牆**，而畫面只放得下摘要或結論其中一個。

右下角的頻道標記和「請訂閱」由程式畫，不用寫。它在訊息落地之後才出現：
剛剛聽懂一件事的人會看一眼是誰讓他聽懂的，**那半秒是唯一會按訂閱的時刻。**

`tone` 建議回到片頭的那一個，收尾成一個圈——順便讓結尾頁不是第十三張同色的畫面。

程式會擋沒有結尾頁的文案。

## tone 跟著論證轉

```
cool    鋪陳（觀眾以為自己知道的版本）
light   翻轉 —— 深色片子中間插一段亮底，最便宜的「事情變了」訊號
warm    落地和結論
```

不是照喜好挑。**一個字都不用花就把結構標出來。**

## 不要連續用同一種形狀

```
同一種 kind   最多連續 {cards.same_kind_run} 張
同一個 tone   最多連續 {cards.same_tone_run} 張（本來就該一整段維持）
```

每一張單獨看都沒問題，**四張排在一起就是投影片**——同樣的字級、同樣的位置、
同樣的底，眼睛沒有東西可以跟。第一版的結尾連續六張 `word`，
而且是把整支片排成一張接觸表才看見的，看單張看不出來。

程式會擋。

## 引用畫面上的字會跟你的卡片打架

新聞畫面自己帶著台標、下標、數字。剪進來的時候那些字也一起進來，
而**觀眾會同時讀到兩個數字**。

```
Fox 的下標    273 DEAD, 1,300+ MISSING
兩秒後的卡片   近 600 人罹難
```

看起來像有人算錯，其實是兩個時間點。程式檢查不到（要 OCR），所以挑段落的時候
自己要看：**畫面上寫了什麼字？跟你接下來要說的對得上嗎？**

對不上的時候，把它變成內容通常比避開好——那支片子的頭幾天，數字一直往上，
本來就是故事的一部分。改成「先報 273，後來近 600」，矛盾就變成資訊。

## 常見的錯

```
同一個事實用兩張卡講      兩張 clock 相隔三句都寫「7 年」
卡片只是一個問號          有數字就用數字（Forbes 說已轉嫁 230 億美元）
講道理的句子硬配照片      比例會爆掉，而且那句本來就更適合用圖表
標籤跟畫面不符            比沒有標籤更糟，因為標籤會被抄進燒錄
```
