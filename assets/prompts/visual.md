# 每一句配什麼畫面

一句台詞一個鏡頭。你要決定**哪一種鏡頭，以及那個鏡頭長什麼樣**。

## 四種鏡頭

```
用影片    事情在發生        現場、群眾、機具在轉、有人在說話
用靜圖    要看清楚一個東西    帳單、電表、圖表、一張臉
用卡片    在講道理          判斷、提問、結論
用情境影片 需要畫面在動，但這件事沒有現場畫面
```

早期的片子**一律用靜圖，等於把第一類也當成第二類處理**，成品從頭到尾
沒有一個畫面在動。無旁白的片子，動態是唯一還在動的東西——
一張人群的照片沒辦法說「事情正在發生」。

**情境影片不是證據。** 它是一支「夕陽下的電塔」，跟這個題目沒有關係，
所以：

```
可以   讓一句過場的話不要停在靜止的畫面上
可以   當一段的開頭或收尾的空景
不行   拿來代表「這件事的現場」
不行   配在一句有出處的事實上 —— 那會讓觀眾以為那是真的畫面
```

它**不算進外部素材的比例**（下面那一節的下限，只有真實照片和新聞片段
算數）。也就是說，多用情境影片不會讓你少用實拍，只會少用卡片。

## 比例

```
外部素材      佔總長 {borrowed.aim:pct}（下限 {borrowed.least:pct}、上限 {borrowed.most:pct}）
其中影片段落   至少佔外部素材的 {borrowed.clip_least:pct}
出現節奏      每三分之一的時間至少一次
```

上面那兩條相乘，就是影片段落的下限：**至少佔總長 {borrowed.clip_share:pct}，
{length.limit_seconds} 秒的片子就是 {borrowed.clip_seconds} 秒**。其餘的外部素材用照片補滿。

**段數自己算**：拿 {borrowed.clip_seconds} 秒去除素材清單上那些段落的長度
（每一段旁邊都標了秒數）——**不要預設固定段數**，段落長短每一題都不一樣，
有的題目段落多是 4-6 秒、湊 {borrowed.clip_seconds} 秒要五六段，有的題目
段落動輒 10 秒以上、兩三段就夠。起訖不用你寫，程式從清單填。

照片補得越多不會讓你少放影片 —— 實拍一多，「一半要會動」要的秒數跟著變多。

兩條線都會擋。上限那條罰的是整個頻道 ——
**別人的畫面佔比一高，YouTube 會判定內容不是我們的**。
下限那條擋的是另一件事：**卡片超過一半，成品就是有聲音的簡報**。

下限一定湊得到，因為**同一張照片可以用在好幾句上**。
湊不到只有一個意思：沒有把收回來的東西看過一遍。

## 影片段落

`clip` 那一格**只寫編號**（`C3` 這種，形狀見 `script.md` 的輸出格式）。檔案、起訖、長度都由程式從候選清單填 —— 那些起訖已經落在
字幕的句子邊界上，自己填數字會從半句開始。剪出來會**保留原聲**。

## 情境影片

`stock` 那一格只寫編號（`V7` 這種，形狀見 `script.md` 的輸出格式）。
**不用寫 `show`**——程式會直接從那支影片的分類跟關鍵字自動填，寫了也會
被蓋掉。

沒有起訖，也不用標 `seen`（池子裡每一支都已經有人看過才留下來）。

## 用到別人的畫面，那一句要標 `seen`

`pic` 或 `clip` 旁邊都要加 `"seen": true`（形狀見 `script.md` 的輸出格式）。
**照片和影片段落都要，漏了那一句會被門擋下來、整份退回。**

程式檢查得到檔案在不在，檢查不到那張圖是不是那句話講的東西 —— 一張標著
「帳單特寫」的圖實際上是牆上的配電箱，那兩件事在程式眼裡一模一樣。所以
`seen` 是一個**宣告**：有人確認過這張圖配這句話。

你手上只有 caption 那一行字，看不到圖。所以只有在 caption 講清楚了那張圖是
什麼、而且跟你的句子對得上的時候才標。**看不出來就換一張**——素材表裡有
三十幾張。

caption 講的是**別的地方**（別座城市、別座湖）的時候，那張圖不能配在一句
**指名這件事**的句子上，但可以配在一句講**類別**的句子上——題目在講安大略湖，
一張蘇必利爾湖的浪可以配「五大湖」，不能配「安大略湖」。`pic`／`clip` 都
**不用寫 `show`**——程式會直接把那張圖的 caption 或那段的逐字稿存進去，
跟你剛剛讀過、拿來判斷合不合用的是同一份，不用另外重寫一次。

## 靜圖怎麼放進直畫面

橫的照片放進 9:16，總有空間要填。填法是**對這張照片的判斷**，不是預設值：

```
fill     裁成滿版。最有力，但丟掉三分之二的寬度
         —— 主角是直的（電塔、人、單一物件）用這個
ground   配當段 tone 的底色。靜圖和卡片才像同一部片
         —— 橫的場景（廠房、街景）用這個
blur     模糊放大的自己當底。永遠不會錯，也因此每張都長一樣
         —— 挑不出來才用
```

## 卡片要指定怎麼畫

`show` 寫「自製：一條線分岔成兩條」是不夠的——那句話要有人事後讀了去畫，
**跟把配電箱配到帳單那句話上是同一種拆法**：寫的人沒看過，畫的人不知道為什麼。

```json
{"show": "自製：一條線分岔成兩條",
 "card": {"kind": "split", "title": "他們算的不是同一件事",
          "branches": ["發電\n夠不夠", "電線\n夠不夠"], "tone": "light"}}
```

字彙：

```
word    一句話佔滿畫面 —— 最常用，也是預設
number  一個數字，會從 0 跑上去      title / value / under / colour / ghost
ring    一個詞，手畫一個圈把它圈起來   title / value / under
swap    劃掉舊的，換上新的           title / was / now
bars    兩三個量比大小              title / rows[[名稱, 數值, 顏色, 標籤]]
split   一條線分岔成兩條             title / branches[兩個]
chain   同一條線上的幾個點           title / points[] / under
queue   一排排隊的人                title / count / under
stack   一份清單                    title / items[]
clock   一段年數，畫成圈             title / value / part(0–1) / under
outro   結尾頁，只能用在最後一句     title / points[3–4] / under
```

共通欄位：`note` 是出處（畫在畫面頂端）、`ghost` 是背後放大的一兩個字、
`bg` 是這張卡自己的背景照片。

## 卡片也可以有背景照片

**預設每一張卡都該挑一張照片當背景**，除非這句話真的找不到任何搭得起來
的圖——空白色底不是比較安全的選擇，是比較沒有花心思的選擇。

`bg` 寫在 `card` 物件**裡面**（形狀見 `script.md` 的輸出格式），跟 `pic`
一樣**只寫素材清單上的編號**，不要猜檔名——查法一模一樣，只是這裡填的是
卡片的背景，不是整句話的鏡頭。

```
可以   任何一種卡（word／number／ring…）都能加 bg，不衝突
不行   新聞畫格不能當卡片背景（素材表「新聞畫格」那一節的那些）——
       卡片背景一定滿版鋪開，畫格邊上的台標、下標會被裁掉
```

**卡片背景一樣要標 `seen`**——它也是「用了素材庫裡的一張圖」，跟這句話
配的鏡頭是不是照片、影片，要求一樣，不會因為它只是背景就例外。

**清單裡真的挑不到合用的，寫 `bg_search` 代替 `bg`**，位置一樣在 `card`
物件裡面，值換成一句英文搜尋詞（例如 `"aerial coastline sunset"`）。
`bg` 和 `bg_search` 只選一個，`bg` 優先。

**寫關鍵字之前，先看下面「卡片背景已經有的關鍵字」那一節**——如果想要的
畫面（例如「鈔票特寫」）已經在那份清單裡，**照抄那個字串**，不要自己另外
想一個意思差不多的新詞（「金錢」「現金」）。同一個關鍵字才會共用同一批
照片；意思一樣但字不一樣，系統會當成兩個不同的東西，各自重新搜一次。

真的找不到接近的，才自己想一個新的關鍵字——用**英文**、講畫面本身
（"aerial coastline sunset"），不要講這句話的意思（不要寫 "renaming
controversy"，那不是一張照片會長的樣子）。

背景照片是別人的圖的話，出處會自動燒進卡片（畫在 `note` 那一行），
不用自己寫；`note` 本來要寫別的東西，兩個會接在一起，不會互相蓋掉。

**這張背景圖不算進「借來的畫面」比例**——跟卡片本身一樣，它是替論證
撐場面的裝飾，不是這一段的證據。真正的證據要用 `pic` 或 `clip` 那句話
本身去扛，不能靠幫卡片挑一張好看的照片來湊那個下限。

**顏色欄位（`colour`、`bars` 每一列的第三格）只有兩種寫法**：留空，或者
`#ff7a4d` 這種色碼。留空是預設，也通常是對的——空的會用那一段 `tone`
自己的顏色，整支片才像同一部片。

寫 `ok`、`warn`、`red` 這種代號會**過了所有的門，然後在畫圖的時候炸掉**：

```
ValueError: unknown color specifier: 'ok'
```

（現在有門擋了，但擋下來的代價是整份退回重寫。）

## 最後一句一定是結尾頁

形狀見 `script.md` 輸出格式裡的最後一句：`card.kind` 是 `outro`，欄位
`points`／`title`／`under`，另外要標 `"seconds": {ending.seconds}`——
這句話要念的字不多，但畫面要留時間讓人讀完三四條摘要，不能只算
`say` 的長度。`points` 是**摘要**，{ending.points} 條。看完整支片的人拿到的是「讓論證成立的
順序」，而那個順序**不等於他帶得走的順序**——所以要重講一次，把整件事收成幾個步驟。

`title` 是**一句帶得走的話**——講給等一下要轉述給朋友的人聽的。**`say` 要念出
`title` 結尾那一段**，逐字對上，只是不用手動換行（換行交給字幕自己的排版）。

`title` 可以在前面多鋪一句只出現在畫面上、不用念出來的話：

```
"title": "帳單漲的不是電費\n是他們插隊用的那條線"
"say":   "是他們插隊用的那條線"
```

但只要 `say` 有講的字，就要逐字出現在 `title` 的結尾——不要另外寫一句沒人會念
出來、也沒有出現在畫面上的旁白。這裡曾經寫過「`say` 通常跟 `title` 不一樣」，
結果是嘴巴講一件事、畫面印另一件事，兩者毫無關係。程式會擋兩者對不上的結尾頁。

版面是用時間堆出來的，不是用空間：摘要一條一條進來、結論在最後一條之後才落下、
頻道標記再更後面。**一次全部印出來就是一面牆**，而畫面只放得下摘要或結論其中一個。

右下角的頻道標記和「請訂閱」由程式畫，不用寫。它在訊息落地之後才出現：
剛剛聽懂一件事的人會看一眼是誰讓他聽懂的，**那半秒是唯一會按訂閱的時刻。**

`tone` 照下面那張表：結尾頁是結論，用 `warm`。不要為了「收尾成一個圈」
回到片頭的 `cool`——結構訊號比對稱重要，順便讓結尾頁不是連續同色的最後一張。

程式會擋沒有結尾頁的文案。

## tone 跟著論證轉

```
cool    鋪陳（觀眾以為自己知道的版本）
light   翻轉 —— 深色片子中間插一段亮底，最便宜的「事情變了」訊號
warm    落地和結論
```

不是照喜好挑。**一個字都不用花就把結構標出來。**

## 不要連續用同一種形狀

```
同一種 kind   最多連續 {cards.same_kind_run} 張
同一個 tone   最多連續 {cards.same_tone_run} 張（本來就該一整段維持）
```

每一張單獨看都沒問題，**四張排在一起就是投影片**——同樣的字級、同樣的位置、
同樣的底，眼睛沒有東西可以跟。第一版的結尾連續六張 `word`，
而且是把整支片排成一張接觸表才看見的，看單張看不出來。

程式會擋。

## 引用畫面上的字會跟你的卡片打架

新聞畫面自己帶著台標、下標、數字。剪進來的時候那些字也一起進來，
而**觀眾會同時讀到兩個數字**。

```
Fox 的下標    273 DEAD, 1,300+ MISSING
兩秒後的卡片   近 600 人罹難
```

看起來像有人算錯，其實是兩個時間點。程式檢查不到（要 OCR），所以挑段落的時候
自己要看：**畫面上寫了什麼字？跟你接下來要說的對得上嗎？**

對不上的時候，把它變成內容通常比避開好——那支片子的頭幾天，數字一直往上，
本來就是故事的一部分。改成「先報 273，後來近 600」，矛盾就變成資訊。

## 常見的錯

（「230 億美元」那條一樣是別支片的數字，不在你的素材裡，這裡只是示範
「有數字就用數字」是什麼意思。）

```
同一個事實用兩張卡講      兩張 clock 相隔三句都寫「7 年」
卡片只是一個問號          有數字就用數字（例如「Forbes 說已轉嫁 230 億美元」）
講道理的句子硬配照片      比例會爆掉，而且那句本來就更適合用圖表
標籤跟畫面不符            比沒有標籤更糟，因為標籤會被抄進燒錄
```

## 封面 —— 另外設計，不是從鏡頭裡選

`lines` 之外，多寫一個 `cover`。這是給人在 YouTube 上**滑到、還沒點進來**
的時候看的，跟片子裡任何一句話配的畫面是兩個不同的問題：片子裡的畫面要
配合那一刻在說什麼，封面只需要讓人想點進來。

固定格式：一張滿版照片（背景）＋一句標語（疊在上面的大字）。頻道 icon
程式自己畫在右下角，不用寫。形狀見 `script.md` 輸出格式裡的 `cover`
那一欄，跟 `lines` 平行、不在裡面。

`pic` 是任選的——挑不出合適的就不寫，程式會用一張固定的預設圖頂著，不會
因為少這一格而整份被擋下來。挑的話，編號不必是 `lines` 裡用過的那張，
規則跟那邊一樣：查素材清單，不要猜檔名。

`tagline` 一定要有，判準：

- **字要少、要大**——縮圖常常只有拇指大，一段完整句子在那個尺寸看不清楚，
  十個字以內比較穩
- **製造「這是什麼？」的懸念，不是重複劇情**——「零」比「零州搜這個新名字」
  好，後者已經把答案講完了，沒有理由再點進去看
- 不用管跟哪一句台詞對不對得上——封面本來就獨立於任何一秒鐘的畫面
- 挑照片的話，那張圖不需要在 `lines` 裡出現過；素材清單上任何一個 `P` 編號
  都可以挑，這裡要的是「有懸念的畫面」，不是「劇情摘要」
