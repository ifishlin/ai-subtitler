# 寫一份短影音文案

從底下的素材寫出一份 {length.limit_seconds} 秒的短影音文案。

**全部用{language.name}**——台詞、卡片上的字、角色名稱，一個簡體字都不行。
有門在檢查，逐字判。

畫面怎麼配、卡片怎麼畫，在 `visual.md`。這份只談**話怎麼說**。

## 先讀，再想，最後才寫

素材裡會有立場不同的媒體。**先找出他們彼此矛盾、或都沒提的地方**——
觀點就長在那裡。

不要從「最重要的事實」開始寫。最重要的事實，五家媒體都講過了，觀眾也看過了。
你要寫的是**他們都沒說的那句話**。

五種地方最容易長出觀點：

- 兩個事實**互相衝突**（那通常表示他們算的不是同一件事）
- 同一件事被**不同的方式解讀**
- 一件事看起來成功了，**其實只成功了一半**
- 所有人都在吵 A，**沒有人在問 B**
- 大家都在看 A，**但真正決定結果的是 B**

這支片不是把新聞縮短成 {length.limit_seconds} 秒。它的任務是：
**先讓觀眾相信一個版本，再讓一個事實把它打破，最後重新理解同一批素材。**

## 觀點的標準

一句話說得完，而且**素材裡沒有任何一篇這樣寫過**。

```
不算觀點   「國債破了四十兆」                 這是事實，人人都報了
不算觀點   「A 說漲、B 說沒漲」               這是彙整
算觀點     「兩邊都對，因為算的不是同一件事」   這是判斷
```

### 一支片只服務一個核心觀點

素材裡可能推得出好幾個判斷，不要全部塞進去。先選一個**最有力、最意外、
最能讓整批素材重新被理解**的判斷，整支片只服務這一個，其他有趣但無關的
觀點捨掉。

判準：**如果一句話拿掉之後，核心觀點仍然完全成立，而且故事更順，那句
通常不需要。**

### 不要把「評論」誤認成「觀點」

下面這些通常不算觀點，只是態度：

```
這很荒謬　這很諷刺　這很重要　這值得關注　雙方各說各話　事情沒有這麼簡單
```

觀點必須回答：**所以我應該怎麼重新理解前面那些事實？** 好的觀點會讓
前面的資料重新排列，態度不會。

## 故事怎麼推進

不要用「起承轉合」想文章。每一句都要標角色，五種：{structure.roles}

```
吸引   讓人停下來：咦，這什麼？
建立   讓觀眾逐漸相信一個版本：真的假的，原來真的是這樣
打破   丟出跟前面預期衝突的事實：等等，不對
解釋   說清楚為什麼前後看似矛盾：原來如此
回報   把新的理解收成一句值得記住、值得轉述的話
```

不是五段固定格式，也不用平均分配，同一功能可以連續很多句。重點是
觀眾的理解要走過這條路：

```
咦？ → 真的假的？ → 等等，不對 → 原來如此 → 所以真正有意思的是……
```

程式會檢查五種都在、順序沒亂、打破出現在前 {structure.turn_before:pct}、
最後一句是回報。**它檢查不了每一段做得夠不夠好**——那是你的事。

### 吸引：先製造問題，不要先交代背景

開頭不是新聞摘要。不要從「某某今天宣布某項政策……」開始——先找素材裡
最奇怪、最反常、最讓人想追問的一件事。第一兩句的任務只有一個：
**讓一個本來不關心這題的人，願意再看五秒。**

判準：聽完這句，觀眾腦中會不會自然冒出「蛤？真的？」或「為什麼？」
如果不會，就還不是吸引。

### 建立：讓觀眾先相信一個版本

接下來不要急著評論。挑兩三個最有力的事實，把第一個印象推到底，讓觀眾
越來越相信「好，看來事情真的就是這樣」。只有先建立得夠牢，後面的打破
才有力。

### 打破：一定要讓前面的理解出問題

這是整支片最重要的一步。不是「另外還有一個事實」，也不是「另一邊也有
不同看法」，而是**出現一件事，讓觀眾發現自己剛剛相信的版本不完整，
甚至可能錯了**。

判準：把這句拿掉，如果觀眾最後對整件事情的理解幾乎沒變，它就不是打破。
第一個真正的打破必須在前 {structure.turn_before:pct} 出現，不要把最有
意思的矛盾藏到最後。

### 解釋：回答「為什麼兩件事可以同時成立？」

打破之後，不要立刻跳到下一個新聞事實。先問：**前面明明成立，後面也
明明成立，為什麼？** 這裡才開始產生真正的觀點——好的解釋不是重新摘要
素材，而是找到素材之間的關係（「A 說漲、B 說沒漲」不是觀點，「兩邊
其實算的是不同東西」才是）。

判準：解釋之後，觀眾回頭看前面那些事實，意思要變得不一樣。只是多知道
一個細節，不算。

### 回報：給觀眾一個「看完值得」的東西

最後不是摘要，也不是新聞式結論——不要寫「因此這件事情仍值得持續關注」
「未來發展還有待觀察」。觀眾已經花了將近 {length.limit_seconds} 秒，
最後要給他一句能帶走的東西：一個新的理解、一個荒謬的反差、一個很準的
比喻、一個直接碰到他的後果、一句他會想轉述給別人的話。

好的回報，該讓觀眾有「喔——原來如此」的感覺；適合詼諧題材時也可以是
「哈，這就尷尬了」——題材嚴肅時不需要搞笑。

「回報」那一句怎麼落在市井小民身上，見下面「結論一定要落在市井小民
身上」那節。

### 結論一定要落在市井小民身上

不管題目多大——戰爭、國債、外交、氣候——最後一句都要回到**一般人身上**。
不是「這件事很重要」，是**「你會在哪裡遇到它」**。

```
不行   「這是全球經濟的重大警訊。」        關我什麼事？
不行   「各國政府必須正視這個問題。」      那是給政府看的
可以   「你不會收到帳單，你會收到分期版。」
可以   「加油站那本帳不會被審計，而那一本是你在付。」
```

判準：把最後一句念給一個不看新聞的人聽，**他要能立刻知道這跟自己有關**。

做不到的時候，通常是因為前面的落地做得不夠——回去找那個「錢、時間、健康、
安全」的接觸點，不要在結論硬凹。

### 「一般人」是誰，題目上已經寫著了

題目頁有一欄「說給誰聽」，**用那一欄，不要自己重新判斷**。

底下那張對照表是用來**填那一欄**的，不是每次寫稿時重猜一次。
表按關鍵字比對，而關鍵字不知道事情：「科技巨頭買下好萊塢」對到科技那一列，
變成「工作可能被取代的人」——實際上那題是講給**付串流訂閱、看新聞的人**聽的。

### 對照表（拿來起頭，不是拿來當答案）

```
國債、通膨、電費   → 每個要付帳單的人
股市、財報、升息   → 股民、有退休金帳戶的人
戰爭、外交         → 加油、繳稅、家裡有役齡孩子的人
醫療、長照         → 排隊看病的人、照顧家人的人
氣候、天災         → 住在會淹的地方、保費會漲的人
科技、AI           → 工作可能被取代的人、電費在漲的人
```

股民也是市井小民，只是接觸點是**帳戶餘額**，不是水電費。所以股市題目的結論
落在「你的持股」上就是落地了，不用硬扯到菜價。

**不要挑最大的那群，挑最痛的那群**——被影響最深的人，才會分享。

## 寫稿前，先完成五個答案

**不要一看到素材就開始填 {length.lines_silent} 句。** 先在心裡回答：

```
1. 吸引：這題最讓人「咦？」的是什麼？
2. 建立：我要先讓觀眾相信什麼？哪兩三個事實最能讓他相信？
3. 打破：哪一個事實會讓這個理解突然出問題？
4. 解釋：為什麼前後看似矛盾的事情可以同時成立？我自己的核心觀點是什麼？
5. 回報：看完之後，觀眾最值得帶走、轉述給朋友的是哪一句？
```

五個答案沒有想清楚以前，不要開始寫 `lines`。

## 語氣

預設詼諧，但**題材決定語氣**。死亡、疾病、災難、戰爭傷亡——**不要開玩笑**。
放不下來的語氣不是風格，是習慣性動作。這種題目改成克制，力氣放在清楚上。

詼諧要來自**比喻**，不是來自嘲笑。

```
好   「左口袋欠右口袋八萬塊，然後宣布自己破產。」
壞   拿罹難人數或病人開玩笑
```

## 每一句的寫法

```
say     台詞。口語，不是書面語。念得出來的
role    {structure.roles} 其中一個
show    只有 `card`（自己畫的卡片）才要寫，開頭「自製：」。
        寫這張卡對應的是哪個真實畫面或事件，不要重複卡片上已經有的字
        （`title`／`value` 那些）——卡片本身看得到那些字，`show` 要答的
        是「這句話配這張卡的理由」，材料表答不出來的那一半。
        `pic`／`clip`／`stock` 不用寫 `show`：材料表上那張圖的說明、
        那一段的逐字稿、那支情境影片的關鍵字，本來就是你剛剛挑它的
        依據，程式會直接拿那份存進去，寫了也會被蓋掉，等於白寫。
from    出處。事實清單上那一則的編號，例如 F3——不要自己重新打一次來源文字，
        程式只認得編號，打錯字或編錯來源都對不出來，會被退回。
        自己的判斷寫「觀點」
```

- **每句 {caption.per_row} 個中文字以內**——直式字幕一行的寬度
- **數字要念出來**：「四十兆」不是「40兆」，「百分之三點四」不是「3.4%」
- 陳述事實的句子**一定要標事實編號**（`F3` 這種，抄事實清單上的），
  不要自己重寫一遍來源文字——編號查得到，重寫的文字看起來很像對，
  查不到才知道錯
- 標「觀點」的是你自己的判斷，不需要編號，但**不能拿來夾帶沒有根據的事實**
- **一句只承擔一種**：要嘛是事實（標事實編號），要嘛是判斷（標「觀點」）。
  「五十州都不買單，這改名只是自嗨」前半事實、後半判斷，`from` 沒辦法決定
  該填哪一種。需要兩者的時候拆成兩句：先寫事實標編號，下一句寫判斷標觀點
- **逐字稿是機器聽打的，人名和數字不可信。** 起訖秒數可靠（切在句子邊界上），
  字不一定。外國人名、地名、機構名要念進台詞，回「事實」那一節核對——
  那裡的名字是人寫的。事實清單裡沒有，就用職稱代替（「曼尼托巴省長」，
  不要猜一個音譯）

## 數量

```
句數      {length.lines_silent} 句
核心觀點  一個
長度      {length.limit_seconds} 秒
```

這是無旁白版：`say` 不會被語音唸出來，觀眾直接讀畫面上的字。讀速抓每秒
{pace.read_per_second} 字，**每句還有下限 {pace.least_seconds} 秒**——
再短的句子也要讓人讀完。第一次做的時候我用保守的每秒 3.7 字，結果 108 秒。

**句數不是建議，是規格。** 三個模型（30B、32B、117B）看到這一段之後
都只寫了四到六句，因為底下原本寫著「不用自己算」—— 那句話的意思是
「不必逐字計秒」，讀起來是「不必負責長度」。

不足會被門擋下來整份退回，而退回一次的代價是整份重寫。
秒數和比例確實不用自己算；**句數要數。**

**不要數觀點句。** 事實句可以很多，只要它們都在幫同一個核心觀點成立——
核心觀點是不是清楚、是不是只有一個，是判斷題，不是比例題。

範圍裡任何一個數字都合法，**不用為了湊到上限硬加句子**——句數少一點，
就讓多數句子接近字數上限，或讓段落本身停留久一點，兩種都到得了
{length.limit_seconds} 秒。

## 一份完整的長度長什麼樣

**下面是另一支片（AI 資料中心推高電價）的骨架，不是這一題的素材。**
它在這裡只有一個用途：讓你看到句子排起來、長度接近下限時有多長。
台詞省略了，`role` 和句子數是真的。

```
01 吸引   …                        pic
02 吸引   …                        clip
03 吸引   …                        card word
04 建立   …                        pic
05 建立   …                        card number
06 建立   …                        clip
07 打破   ←── 在第 7 句，此時累積秒數在總長的 34% 之內
08 打破   …                        card split
09 打破   …                        pic
10 打破   …                        card ring
11 解釋   …                        card chain
…
18 解釋   …                        card word
19 回報   …                        card outro（結尾頁，最後一句）
```

19 句，`打破` 落在第 7 句——只要累積到那裡的秒數沒超過總長的 34%，就算合格，
不是「第幾句」這個位置本身有意義。如果你寫到第 5、6 句就準備收尾，那不是
精簡，是句數不夠、內容漏了大半。

## 輸出格式

只輸出 JSON，不要別的。**圖和影片段落用素材清單上的編號，不要寫檔名**：

**下面是唯一的輸出形狀**——四種鏡頭、`seen`、`bg`、結尾頁、封面，
一次示範完。`visual.md` 講的是「這個欄位什麼時候該填、填什麼值」，
形狀只看這裡，後面不會再出現另一種寫法：

```json
{
  "view": "一句話講完你的觀點",
  "tone": "詼諧 或 克制",
  "cover": {"pic": "P30", "tagline": "十個字以內、製造懸念的一句標語"},
  "lines": [
    {"say": "台詞", "role": "角色", "show": "自製：這張卡對應的真實畫面或事件",
     "card": {"kind": "word", "title": "…", "bg": "P16"}, "from": "F1"},

    {"say": "台詞", "role": "角色",
     "pic": "P18", "seen": true, "from": "F3"},

    {"say": "台詞", "role": "角色",
     "clip": "C3", "seen": true, "from": "F5"},

    {"say": "台詞", "role": "角色",
     "stock": "V7", "from": "觀點"},

    {"say": "帶得走的一句話", "role": "回報", "show": "自製：結尾頁",
     "seconds": {ending.seconds},
     "card": {"kind": "outro", "tone": "warm",
              "points": ["摘要一", "摘要二", "摘要三"],
              "title": "……帶得走的一句話", "under": "題目一句話"},
     "from": "觀點"}
  ]
}
```

`P18`、`C3`、`V7` 就是上面素材清單裡那個編號，照抄。**寫檔名一定會錯**——
編號查得到，檔名要記，而記錯的檔案往往真的存在（是別的題目的），
看起來完全合理。`bg` 也是同一種編號，寫在 `card` 物件**裡面**。

`clip` 只寫編號，起訖秒數由程式從清單填。最後一句一定是這種
`outro` 卡——`points`、`title`、`under` 怎麼寫，見 `visual.md`
「最後一句一定是結尾頁」那節。

## 最後檢查

- [ ] **`lines` 的長度是 {length.lines_silent} 句嗎？數一遍。**
      不足會被退回重寫，那是最常見的失敗 —— 三個模型（30B、32B、117B）
      在這裡都只寫了四到六句。
- [ ] 這支片能不能用一句話說出自己的核心觀點？
- [ ] 這句話是不是素材裡沒有任何一篇直接這樣寫？
- [ ] 它是不是由素材中的事實關係推導出來，而不是憑空評論？
- [ ] 打破之前，觀眾相信的是什麼？解釋之後，觀眾相信的是什麼？
      這兩個答案真的不同嗎？
- [ ] 第一個真正的「打破」有在前 {structure.turn_before:pct} 出現嗎？
- [ ] 最後一句是「回報」嗎？是不是觀眾會記得、會轉述的話？
- [ ] 有沒有為了顯得有態度，而加入其實不必要的評論句？
- [ ] 每一句陳述事實的，`from` 是事實清單上那一則的編號嗎（`F3` 這種）？
      自己重寫一遍來源文字不算，程式只認編號，對不出來會被退回
- [ ] 這個題材適合開玩笑嗎？
- [ ] 這題目最直接影響的是哪一群人？結論是寫給他們聽的嗎？
- [ ] 最後一句，那群人聽了會知道跟自己有關嗎？
- [ ] 每一句**有且只有一種**鏡頭：`pic`、`clip`、`card`、`stock` 四選一，
      只寫 `show` 不算，一句也不要同時塞兩種（例如 `pic` 又加 `card`）。

比例、出處、五段結構這幾項程式會算，寫錯會被門擋下來重寫 ——
**但句數要你自己數**，那一項沒有人能替你補。
